# 会员风采列表分页改造

日期：2026-11-12

## 一、需求

会员风采（风采广场 / 我的发布）原先一次性拉取 40 / 50 条数据，首屏过重。改为分页加载：

- 每页 6 条（双列瀑布流 = 3 行）
- 按时间倒序，最新的排在最前
- 底部「加载更多」按钮累加下一页，加载完显示「没有更多了」

## 二、改动内容

### 1. 前端 `vue3-jianshenfang`

| 文件 | 改动 |
| --- | --- |
| `src/views/moments/SquareView.vue` | `api.moments('all', 1, 40)` → 每页 `PAGE_SIZE = 6`；新增 `page` / `total` / `loadingMore` / `finished` 与 `loadMore()`；模板底部加分页条 |
| `src/views/moments/MineView.vue` | `api.moments('mine', 1, 50)` → 每页 `PAGE_SIZE = 6`；同样新增分页状态与 `loadMore()`；删除后改为本地移除并同步 `total`，不再整表重载导致跳回顶部 |
| `src/styles/moments.css` | 新增 `.load-more` 分页条样式（按钮 / 加载中禁用态 / 没有更多文案） |

分页逻辑要点：

- 首次进入 `load()`：`page = 1`，`total` 取接口返回的 `total`
- `loadMore()`：请求 `page + 1`，用 `concat` 追加，保持已渲染的瀑布流顺序不重排
- `finished = list.length >= total`，为 `true` 时隐藏按钮，避免无意义的空请求
- 请求期间 `loadingMore` 置位并禁用按钮，防止连点重复请求

### 2. 后端 `jianshenfang`

**无需改动**。`MomentController#list` 与 `MomentService#list` 已满足要求：

- `size` 已做上限收敛：`int s = Math.min(50, Math.max(1, size))`，前端传 6 合法
- 排序已为 `w.orderByDesc(Media::getId)`，自增主键倒序即发布时间倒序（最新在前）
- 返回 `PageVO(list, total, page, size)`，前端可据此判断是否还有下一页

## 三、SQL 变更

**本次无 SQL 变更**，不涉及建表、加字段、索引或数据订正，无需执行任何 DDL/DML 脚本。

（`media` 表已有 `id` 主键自增，列表排序走主键倒序，现有索引足够，无需新增索引。）

## 四、执行顺序

1. 前端发布：`npm run build` 产出 `dist`，按现有流程部署到静态站点（本次已验证构建通过）
2. 后端无需重新发布（无代码与 SQL 变更）
3. 浏览器验证：进入 `/moments` 与 `/moments/mine`，首屏应只有 6 条，点「加载更多」追加 6 条，全部加载完显示「没有更多了」，且最新发布的排在最前
