# 公众号自定义菜单（会员登录）

日期：2026-11-13

## 一、需求

在已接入的微信**测试号**下增加自定义菜单，菜单项「会员登录」，点击后完成微信网页授权并进入会员端 H5。

## 二、关键结论

1. **测试号后台没有「自定义菜单」可视化编辑器**（只有正式号才有），测试号建菜单只能调接口 `cgi-bin/menu/create`。
2. 菜单的 `view.url` **不能直接填 H5 页面**，必须指向后端入口 `/wechat/oauth/entry`，由后端 302 到微信授权页；授权完成后回调 `/wechat/oauth/callback`，再 302 回 H5 的 `/wechat/entry?ticket=xxx`。
3. `url` 域名必须与公众号后台的**网页授权域名**一致（测试号可填域名，无需备案）。

默认菜单（不传 body 时生成）：

```json
{
  "button": [
    {
      "type": "view",
      "name": "会员登录",

    }
  ]
}
```

## 四、部署前置条件

### 1. 测试号参数确认

- 测试号 `appid` / `secret` 已配置在 `config/wechat-dev.properties` + `application-dev.yml`
  （当前 appid `wxdc874e48e6e85235`），`wx.mock` 必须为 `false`
- 测试号后台「接口配置信息」URL 填 `https://13230zl69xe33.vicp.fun/wechat/event`，Token 填 `wx.token` 同值
- 测试号后台「网页授权获取用户基本信息」域名填 `13230zl69xe33.vicp.fun`（不带 `https://`、不带路径）

### 2. 内网穿透

`vite.config.ts` 已把 `/api`、`/wechat/oauth`、`/wechat/event` 代理到 `localhost:8080`，因此：

- 花生壳隧道 → 本机 **5173**（Vite）
- 后端 8080 不用直接对外暴露

授权回调走同域名的 `/wechat/oauth/callback`，能被 Vite 代理到后端，链路成立。

> 隧道必须指向 **5173（前端）**。若指向 8080（后端），`/wechat/oauth/entry` 能进授权，但授权完成后回跳的
> `/wechat/entry?ticket=xxx` 是**前端路由**，后端没有这个地址，会返回 404（本次遇到的问题）。

### 3. 生产 Nginx 必须补 /wechat 反向代理

`docs/第一版整体设计及服务器部署.md` 里的 Nginx 片段只配了 `/api/`、`/upload/`，
`/wechat/**` 会落到 `try_files ... /index.html`，导致后端入口根本不被调用。生产需补：

```nginx
location /wechat/oauth/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /wechat/event {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

`/wechat/entry`、`/wechat/bind`、`/wechat/follow` 是**前端路由**，不能反代到后端，
必须继续由 `location / { try_files $uri $uri/ /index.html; }` 处理。

## 五、执行步骤

1. 启动后端与前端（`npm run dev`、Spring Boot `dev` profile），确保隧道域名可访问。
2. 用管理员账号登录管理端拿到 JWT（`Authorization: Bearer xxx`）。
3. 取 access_token（等价于 `https://api.weixin.qq.com/cgi-bin/token?appid=&secret=&grant_type=client_credential`，但走应用缓存，不会把线上 token 顶掉）：

```bash
curl https://13230zl69xe33.vicp.fun/api/admin/wechat/access-token \
  -H "Authorization: Bearer <管理员JWT>"
# => {"code":0,"data":{"accessToken":"...","expiresIn":6900,"expireAt":"2026-11-13 23:40:00"}}
```

临时换另一个公众号的 token（只换不缓存）：

```bash
curl -X POST https://13230zl69xe33.vicp.fun/api/admin/wechat/access-token \
  -H "Authorization: Bearer <管理员JWT>" -H "Content-Type: application/json" \
  -d '{"appid":"wxdc874e48e6e85235","secret":"<secret>"}'
```

拿到的 `accessToken` 可直接用于微信调试工具里的 `cgi-bin/menu/get`、`cgi-bin/menu/create` 等接口。

4. 创建默认菜单：

```bash
curl -X POST https://13230zl69xe33.vicp.fun/api/admin/wechat/menu \
  -H "Authorization: Bearer <管理员JWT>" \
  -H "Content-Type: application/json"
```

5. 需要多个按钮时传自定义 body（整体覆盖，最多 3 个一级菜单、每个最多 5 个二级菜单）：

```bash
curl -X POST https://13230zl69xe33.vicp.fun/api/admin/wechat/menu \
  -H "Authorization: Bearer <管理员JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "button": [
      {"type":"view","name":"会员登录","url":"https://13230zl69xe33.vicp.fun/wechat/oauth/entry?redirect=/"},
      {"type":"view","name":"我的预约","url":"https://13230zl69xe33.vicp.fun/wechat/oauth/entry?redirect=/bookings"},
      {"type":"view","name":"会员风采","url":"https://13230zl69xe33.vicp.fun/wechat/oauth/entry?redirect=/moments"}
    ]
  }'
```

6. 校验：`GET /api/admin/wechat/menu` 返回微信侧当前菜单。
7. 手机上取关再关注（或杀进程重进公众号）查看菜单；微信客户端有缓存，最多延迟数分钟。

> 说明：接口内部复用应用已缓存的 `access_token`，**不要**在外部另行调 `cgi-bin/token`，否则可能让正在运行的应用的旧 token 失效，导致模板消息报 `40001`。

## 六、注意事项

- ~~生产配置笔误~~：`application-prod.yml` 中 `callback-base-url` 原为 `hhttps://kai27ks.cn`（多一个 `h`），已于 2026-11-13 修正为 `https://kai27ks.cn`。
- 菜单 `name` 不超过 16 字节（约 5 个汉字），「会员登录」占 12 字节，安全。
- `view.url` 必须 https 且与网页授权域名完全一致，否则点击无响应或提示「该公众号暂时无法提供服务」。
- 菜单点击后若会员未绑定：进入认领页（手机号 + 认领码），不会自动建档。
