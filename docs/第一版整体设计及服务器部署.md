# 私教工作室管理系统 · 第一版整体设计及服务器部署

> 版本：V1 设计稿（不含实现）
> 适用场景：单店私教 1V1 工作室，员工 / 管理者 / 会员三类使用者
> 硬件条件：单台 2 核 4G 云服务器承载全部服务，同时上课人数 ≤ 20

---

## 一、目标与范围

### 1.1 建设目标

为私教 1V1 工作室提供一套轻量的辅助管理工具，覆盖「账号 → 会员 → 课程 → 约课 → 到点自动签到扣课 → 通知 → 报表」的完整闭环，不做多门店、不做复杂营销体系。

### 1.2 第一版范围

| 范围 | 内容 |
| --- | --- |
| 包含 | 注册登录与找回密码、会员管理、课程模板、教练管理（资质/简介/请假）、会员课包、约课/取消、**到点自动签到并扣减课时**、公众号模板消息通知、管理员报表（财务类 + 课程类） |
| 不包含（二期） | 会员风采（照片/视频上传）、生日营销提醒、图表化报表、退课退款流程 |

### 1.3 角色

| 角色 | 说明 | 账号来源 |
| --- | --- | --- |
| 管理员 ADMIN | 工作室管理者，看全部数据、管报表、管教练与课包价格 | 系统初始化 / 管理员创建 |
| 教练 COACH | 排课、请假、看自己的会员与预约 | 管理员后台创建，禁止自行注册 |
| 会员 MEMBER | 查看自己的课包与预约、约课、取消 | 手机号自助注册，或管理员代录 |

### 1.4 权限矩阵

| 功能 | 管理员 | 教练 | 会员 |
| --- | :---: | :---: | :---: |
| 报表（财务 / 课程） | ✅ | ❌ | ❌ |
| 教练新增/编辑 | ✅ | 仅本人资料 | ❌ |
| 会员新增/编辑/绑定教练 | ✅ | 仅自己名下会员 | 仅本人 |
| 课程模板维护 | ✅ | 只读 | 只读 |
| 课包（价格/节数）编辑 | ✅ | ❌ | ❌ |
| 请假 | ✅（代录） | ✅ | ❌ |
| 约课 | ✅ | ✅ | ✅ |
| 取消预约 | ✅ | ✅（随时） | ✅（开始前 ≥2h） |
| 手动补签 | ✅ | ✅（自己课） | ❌ |
| 课时手动增减 | ✅ | ❌ | ❌ |

## 二、功能模块设计

### 2.1 认证模块

- **注册**：手机号 + 图形/短信验证码；仅允许注册为会员；教练与管理员账号由后台创建。
- **登录**：手机号 + 微信验证码登录；手机号 + 密码登录（二选一）。
- **重置密码**：手机号 + 验证码 → 设置新密码。
- 要求：
  - 密码使用 BCrypt 加盐存储；
  - 验证码限流：同手机号 60 秒 1 条、单日 ≤ 10 条、同 IP 单日 ≤ 30 条；
  - 会话使用 JWT（无状态），有效期 7 天，前端存本地存储。

### 2.2 会员管理

- 字段：姓名、手机号（唯一）、性别、生日、（可选）头像。
- 会员与教练 **1 对 1 绑定**：会员档案上有 `coach_id`，管理员可改绑；教练只能看到名下会员。
- 会员列表支持按姓名/手机号/绑定教练筛选。
- 会员详情页聚合展示：基本信息、当前课包（剩余节数/有效期）、历史预约、消课记录。

### 2.3 课程体系（课程模板）

- 字段：课程名称、单节时长（分钟）、默认课节数、状态。
- **无价格**；价格落在「会员课包」上。
- **无固定排期**：教练不排固定班表，上课时间由会员预约决定；只要教练当天未请假，营业时间内任意空闲时段均可约。
- 模板用途：约课时选择课程、决定默认时长与展示文案。

### 2.4 教练管理

- 字段：姓名、手机号（登录账号）、照片、简介、状态（在职/停用）。
- **资质管理**：一个教练多条资质（证书名称、编号、发证机构、图片、有效期）。
- **请假**：
  - 可提交多段请假（开始时间、结束时间、事由）；
  - 请假时间段内不可被约课，约课接口直接校验；
  - 若请假与已约课程冲突：不静默失效，系统列出冲突预约并通知教练与管理员，由教练走取消流程后与会员重新预约（系统无改期功能）。
- 教练停用后：不可排课、不可约课，名下会员需管理员改绑。

### 2.5 会员课包（核心）

- 一个会员可有多张课包，每张课包：课程模板、**总节数**、**剩余节数**、**总价（可编辑）**、购买时间、有效期、状态。
- 管理员可编辑价格与节数；可手动补/扣课时（必须填写备注，写操作日志）。
- 课时扣减在**自动签到成功时**发生，一次扣 1 节。
- 有效期到期前 7 天提醒（通知渠道同下）。

### 2.6 约课 / 取消 / 自动签到（核心流程）

**状态机**

```
待上课(BOOKED) ──到点自动签到──▶ 已签到(CHECKED_IN) ──▶ 已完成(COMPLETED)
      │
      ├──会员取消(开始前≥2h)──▶ 已取消(CANCELED)
      └──教练取消(随时)──▶ 已取消(CANCELED)
```

**约课**

- 入参：会员、课程模板、教练、开始时间、所属课包。
- 校验链：会员有效 → 绑定教练与所选教练一致（1V1 约束）→ 课包剩余节数 > 0 且未过期 → 教练该时段无请假 → 教练该时段无占用 → 会员该时段无冲突 → 会话教练不可重复。
- 并发控制：`booking` 表对 `(coach_id, start_time)` 建唯一索引 + 事务插入，避免超约。
- 成功：生成预约，发送公众号通知给会员与教练。

**取消 / 修改**

- **预约成功后不可修改**（时间、教练、课程均不可改）；需要调整时先取消再重新预约，非特殊情况不建议操作。
- 会员：距开始时间 ≥ 2 小时可取消；不足 2 小时前端禁用按钮，后端同样校验。
- 教练：随时可取消，必须填写原因。
- 已签到：任何角色不可取消。
- 取消不涉及课时增减（课时在签到时才扣）。
- 成功：发送通知给双方（教练取消时通知会员 + 管理员）。

**自动签到（仅针对会员）**

- 教练不设签到功能（默认在场）；自动签到对象仅为会员，目的是提高会员上课率——到点即签到、扣课时，倒逼会员按时到场。
- 定时任务每分钟执行一次：
  - 扫描 `status = BOOKED AND start_time <= now()`；
  - 逐条以 CAS 方式 `UPDATE ... SET status = CHECKED_IN WHERE id = ? AND status = BOOKED`，更新成功者才扣课时；
  - 扣课时使用条件更新 `UPDATE member_package SET remain = remain - 1 WHERE id = ? AND remain > 0`，避免超扣；
  - 若剩余节数为 0（异常数据），标记为「待处理」并通知管理员，不阻断流程。
- 幂等保证：靠状态 CAS，重复执行不会重复扣课。
- 课程结束时（`start_time + duration`）由同一任务置为已完成（仅状态流转，不涉及金额）。
- **手动补签**：管理侧「打卡」入口，用于服务端故障或补录场景，仅管理员/该课教练可操作，同样走扣课逻辑并记录日志。

### 2.7 通知（微信公众号模板消息）

- 渠道：微信公众号模板消息（需已认证服务号 + 用户已关注）。
- 触发场景：约课成功、会员取消、教练取消、课包临期提醒。
- 模板字段（与现有模板对齐）：

| 字段 | 变量 | 示例 |
| --- | --- | --- |
| 会员姓名 | `{member_name}` | 毛文坊 |
| 会员电话 | `{member_phone}` | 13705957281 |
| 课程类型 | `{course_name}` | 陈筱鹭基础私教 |
| 课程开始时间 | `{start_time}` | 2026年11月05日 09时30分 周四 |
| 预约时间 | `{book_time}` | 2026年11月02日 18时11分 周一 |
| 查看详情 | 跳转链接 / 小程序页 | /booking/{id} |

- 实现要点：
  - 通知能力抽象为 `NotifyService` 接口，第一版实现为「公众号模板消息」，将来换短信不改业务代码；
  - `notify_template` 表可配置：场景、模板 ID、字段映射、启用开关、跳转地址；
  - 发送走异步（线程池），失败记录 `notify_log` 并重试 1 次，不阻塞约课主流程；
  - 未关注公众号的会员降级处理：管理端可见「未送达」标记，可由教练口头/微信私聊告知。
- ⚠️ 前提确认：订阅号或不支持模板消息的小程序无法使用本方案，需改用「订阅通知」或小程序订阅消息（需用户逐次授权，体验下降）。

### 2.8 报表（管理员）

- **财务类**：课包销售额（按时间段/课程/教练）、总收入趋势、会员消费排行。
- **课程类**：消课总量、各教练上课量排名、约课取消率、课程满课率（1V1 场景即课时利用率）。
- **工作台首页卡片**（对应管理端主页设计）：今日会员、今日营收、今日上课，各带月累计；数据来自同一聚合接口，日切按服务器时区 0 点。
- 第一版呈现方式：表格 + 简单柱状/折线（ECharts），支持导出 Excel。

### 2.9 管理端主页（工作台）

对应现有原型：

- **顶部**：工作室名 / 头像 + 今日统计三卡（今日会员、今日营收、今日上课，含月累计）。
- **快捷入口**：添加会员、会员管理、我的预约、打卡（手动补签）、请假。
- **底部导航**：工作台 / 预约 / 报表 / 我的。
- 角色差异：教练登录隐藏「今日营收」金额与「报表」入口；会员端无此页。

### 2.10 会员风采展示（二期）

- 会员上传照片（≤ 1M）与视频（≤ 10 秒）；
- 前端录制/裁剪限制 + 后端二次校验（大小、时长、格式，图片统一压缩）；
- 提交后进入审核队列，管理员通过后展示；
- 文件存本地磁盘目录，Nginx 直接静态响应。

## 五、技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言/运行时 | **Java 21** | 与现有工程一致 |
| 后端框架 | **Spring Boot 3.x**（单体） | 一个可执行 jar，无需微服务 |
| ORM | **MyBatis-Plus** | 简单 CRUD 效率高 |
| 数据库 | **MySQL 8**（单机） | 并发 20 人约等于空载；`innodb_buffer_pool_size` 调至 512M |
| 鉴权 | Spring Security + JWT（或 Sa-Token） | 无状态，简单 |
| 定时任务 | Spring `@Scheduled` | 自动签到、临期提醒，量级小无需 Quartz/XXL-Job |
| 通知 | 微信公众号模板消息 | 抽象成 `NotifyService` 便于换渠道 |
| 缓存 | **第一版不用 Redis** | 单机低并发，验证码可用本地 Caffeine 缓存；后续需要再上 |
| 前端（管理/教练端） | Vue 3 + Element Plus（H5，适配手机浏览器/微信内置浏览器） | 对应原型为移动端 H5 形态 |
| 前端（会员端） | 同一套 H5 或微信小程序 | 建议第一版统一 H5，减少一套工程 |
| 反向代理 | Nginx | 静态资源 + 反向代理 + HTTPS |
| 文件存储 | 本地磁盘 + Nginx 静态目录 | 照片/资质图量小，定期备份即可 |

> 关于 Microsoft Access：**不推荐**。Linux 服务器无法运行、并发与驱动支持差、Java 生态缺失、迁移成本高。若想省去数据库运维，可用 **SQLite**（单文件、零进程、备份即拷贝文件）作为替代，但本项目 4G 内存完全容得下 MySQL，推荐直接上 MySQL。

## 六、服务器部署方案（2C4G 单机）

### 6.1 架构拓扑

```
           Internet (HTTPS)
                  │
        ┌─────────▼─────────┐
        │   Nginx :443      │  静态资源 / 反代 / TLS
        └────┬─────────┬────┘
             │         │
   /api/*    │         │  /upload/*、/*.html、/*.js
             ▼         ▼
   ┌────────────────┐  ┌──────────────┐
   │ Spring Boot    │  │ /var/www     │
   │ 127.0.0.1:8080 │  │ 前端静态文件 │
   └───────┬────────┘  └──────────────┘
           │ JDBC
   ┌───────▼────────┐
   │ MySQL 8 单机   │
   └────────────────┘
```

### 6.2 软件清单

| 组件 | 版本建议 | 说明 |
| --- | --- | --- |
| OS | Ubuntu 22.04 / 24.04 LTS（或 CentOS Stream / Rocky 9） | 长期支持版本 |
| JDK | Temurin 21 | 与 Spring Boot 3 匹配 |
| MySQL | 8.0.x | 单机本地连接 |
| Nginx | 1.24+ | 静态 + 反代 |
| 证书 | Let's Encrypt (certbot) | 免费，自动续期 |
| 进程管理 | systemd | 开机自启、崩溃自拉起 |

### 6.3 内存预算（4G）

| 进程 | 建议上限 |
| --- | --- |
| 操作系统 + 常驻服务 | ~500 MB |
| MySQL（buffer pool 512M + 连接与缓存） | ~900 MB |
| Spring Boot JVM（`-Xms512m -Xmx1536m`） | ~1.8 GB |
| Nginx | ~50 MB |
| 余量 | ≥ 700 MB |

建议额外配置 **2G swap** 兜底（`vm.swappiness=10`），防止突发内存峰值触发 OOM Kill。

### 6.4 部署步骤（概要）

1. 系统初始化：创建 `app` 用户、关闭 root 远程登录、开启防火墙（仅放行 22/80/443）。
2. 安装 JDK 21、MySQL 8、Nginx。
3. MySQL：创建库 `fitness`、专用账号、字符集 `utf8mb4`；`my.cnf` 设置 `innodb_buffer_pool_size=512M`、`max_connections=100`。
4. 后端：上传 `app.jar` 至 `/opt/fitness/`，配置 `application-prod.yml`（数据库、微信 appid/secret、上传目录），用 systemd 托管：

```ini
# /etc/systemd/system/fitness.service
[Unit]
Description=Fitness Studio API
After=network.target mysql.service

[Service]
User=app
WorkingDirectory=/opt/fitness
ExecStart=/usr/bin/java -Xms512m -Xmx1536m -jar /opt/fitness/app.jar --spring.profiles.active=prod
Restart=always
RestartSec=5
StandardOutput=append:/var/log/fitness/app.log
StandardError=append:/var/log/fitness/app.log

[Install]
WantedBy=multi-user.target
```

5. 前端：构建产物放 `/var/www/fitness/`，Nginx 配置 `try_files $uri $uri/ /index.html`（SPA 路由）。
6. Nginx 关键配置：

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    client_max_body_size 12m;          # 视频上传留余量

    root /var/www/fitness;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /upload/ {
        alias /opt/fitness/upload/;
        expires 7d;
    }
}
```

7. 微信公众平台配置：服务器域名（业务域名 / 网页授权域名 / JS 接口安全域名）指向该域名，必须 **HTTPS + 已备案**；配置 IP 白名单（服务器公网 IP）以调用模板消息接口。

### 6.5 备份与运维

## 七、安全要点

1. 密码 BCrypt；登录失败 5 次锁定 10 分钟。
2. 验证码全链路限流（手机号 + IP 双维度）。
3. 所有列表接口做数据权限过滤：教练只能查自己名下数据，会员只能查自己数据。
4. 手机号在教练端默认脱敏展示（可配置开关）。
5. 上传文件校验 MIME + 扩展名 + 大小，图片重编码去掉 EXIF，文件名随机化，禁止脚本执行。
6. 敏感操作（改价、调课时、补签、删预约）写 `operation_log`。
