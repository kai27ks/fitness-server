# 工作台与「我的」页姓名硬编码修复

## 现象

管理端首页（工作台）左上角显示「管理员/教练 · 陈筱鹭」，与实际登录人不一致；进入「我的」页后却能显示正确姓名（当登录人有关联教练档案时）。

截图中的「03 健身工作室」来自 `/admin/dashboard` 的 `studioName`，是正确的；写死的是后面的人名。

## 原因

两处模板把示例姓名写进了前端：

- `src/views/admin/WorkbenchView.vue`：`<small>{{ role === 'ADMIN' ? '管理员' : '教练' }} · 陈筱鹭</small>`
- `src/views/admin/MineView.vue`：`<b>{{ coach?.name || '陈筱鹭' }}</b>`，且只有 `role === 'COACH'` 时才请求 `/coaches/me`，管理员不请求，所以兜底值一直是写死的人名。

## 改动内容（仅前端）

| 文件 | 改动 |
| --- | --- |
| `src/views/admin/WorkbenchView.vue` | 新增 `staffName`；挂载后调用 `api.coachMe()` 取当前登录人对应的教练档案姓名，失败时静默回退为「管理员 / 教练」；标题改为 `角色 · 真实姓名` |
| `src/views/admin/MineView.vue` | 不再限制角色，`ADMIN` 也请求 `api.coachMe()`；头像首字与姓名兜底改为「管 / 教」「管理员 / 教练」，不再写死人名；两个请求拆开，任一失败不影响另一块展示 |

姓名来源：`GET /api/coaches/me`（`AuthUtil.requireStaff()`，管理员与教练都可访问）→ `CoachAdminService.currentCoach()` 按 `AuthContext.userId()` 查 `coach.user_id`。

边界：如果登录账号**没有关联教练档案**，该接口会返回「未找到教练档案」，前端静默忽略，页面显示通用称呼「管理员 / 教练」而不是报错或假名字。如需显示真实姓名，给该账号补一条教练档案即可。

## SQL 变更

本次上线**没有 SQL 变更**，无需执行任何 DDL/DML。

核对当前账号是否关联教练档案（只读）：

```sql
-- ByName / ByPhone 二选一，改成实际登录人的信息
SELECT u.id AS user_id, u.phone, u.role,
       c.id AS coach_id, c.name AS coach_name, c.status AS coach_status
FROM sys_user u
LEFT JOIN coach c ON c.user_id = u.id
WHERE u.phone = '13850943504';
```

若需要补档案（仅在确实需要显示姓名/以教练身份使用时执行）：

```sql
INSERT INTO coach (user_id, name, status)
SELECT u.id, '实际姓名', 1
FROM sys_user u
WHERE u.phone = '13850943504'
  AND NOT EXISTS (SELECT 1 FROM coach c WHERE c.user_id = u.id);
```
