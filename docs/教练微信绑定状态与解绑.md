# 教练微信绑定状态与解绑

## 需求背景

教练从公众号进入时，需要先用自己的登录手机号 + 密码完成微信绑定（`wechat_account` 表记录 `user_id` 与 `openid` 的对应关系）。此前管理端只能「解绑」但看不到是否已绑定，管理员无法判断该教练当前是否还能直接走公众号进入。

本次在教练详情页的「登录账号」卡片中补上微信绑定状态展示，并在已绑定时提供「解绑微信」操作。

## 功能说明

- 查看：进入「我的 → 教练管理 → 教练详情」，在「登录账号」卡片内新增「公众号微信绑定」一行，显示「微信已绑定 / 微信未绑定」，已绑定时附带微信昵称与 openid 尾号。
- 解绑：仅已绑定时出现「解绑微信」按钮，点击需二次确认（提示解绑后需重新用手机号 + 密码绑定）。
- 解绑后该教练再次从公众号进入，会回到手机号 + 密码绑定流程；教练登录账号本身不受影响，账密登录仍可正常使用。
- 解绑逻辑复用原有接口，操作会写入操作日志（`UNBIND_COACH_WECHAT`）。
- 教练没有登录账号（`coach.user_id` 为空）时状态显示为「微信未绑定」，解绑接口会返回「该教练还没有登录账号」。

## 接口变更

| 方法 | 路径 | 用途 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/admin/coaches/{id}/wechat-bind` | 查询该教练微信绑定状态 | 管理员 |
| DELETE | `/api/admin/coaches/{id}/wechat-bind` | 解绑该教练微信（原有接口） | 管理员 |

GET 返回结构：

```json
{ "bound": true, "openidTail": "a1b2", "nickname": "微信昵称", "avatarUrl": "https://..." }
```

未绑定时 `bound=false`，其余字段为 `null`。

## 代码改动

- 后端 `CoachAdminService` 新增 `wechatBind(Long coachId)`，按 `coach.user_id` 复用 `WechatBindService.bindInfoByUser` 查询绑定信息。
- 后端 `CoachAdminController` 新增 `GET /admin/coaches/{id}/wechat-bind`，入口处 `AuthUtil.requireAdmin()` 校验管理员权限。
- 前端 `src/api/index.ts` 新增 `CoachWechatBind` 类型与 `coachWechatBind` 接口封装（`unbindCoachWechat` 已存在）。
- 前端 `src/components/CoachAccountPanel.vue` 在账号信息加载时同步拉取绑定状态，新增展示区与「解绑微信」按钮，解绑成功后重新加载状态。

## SQL 变更

本次上线**没有表结构变更**，无需执行 DDL。

解绑操作由程序执行，等价 DML 如下（仅用于排查与手工修复参考，请勿随意在生产环境直接执行）：

```sql
-- 1. 查询某教练的微信绑定情况（只读核对）
SELECT c.id AS coach_id, c.name, c.user_id,
       w.appid, RIGHT(w.openid, 4) AS openid_tail, w.nickname
FROM coach c
LEFT JOIN wechat_account w ON w.user_id = c.user_id
WHERE c.id = /* 教练ID */;

-- 2. 管理端「解绑微信」对应的等价语句
DELETE FROM wechat_account WHERE user_id = /* 该教练的 sys_user.id */;
```

清理后的数据校验：

```sql
-- 应为 0 行
SELECT * FROM wechat_account WHERE user_id = /* 该教练的 sys_user.id */;
```

如需批量排查存在多绑定或历史残留的教练，可参考：

```sql
SELECT user_id, COUNT(*) AS cnt
FROM wechat_account
GROUP BY user_id
HAVING COUNT(*) > 1;
```
