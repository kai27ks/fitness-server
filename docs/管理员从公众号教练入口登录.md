# 管理员从公众号「教练工作台」入口登录

## 需求与现状

希望管理员也能像教练一样，从公众号「教练工作台」菜单进入并免密登录。

改代码前的行为：

- **已绑定微信的管理员**：本来就能进。`exchangeTicket` 只在角色为 `COACH` 时校验 `coach.status`；ADMIN 走同一条票据链路，签发 `role=ADMIN` 的 JWT，前端跳 `/admin/workbench`。
- **未绑定微信的管理员（本次场景）**：进不去。首次绑定接口 `coachClaim` 强制 `role=COACH`，ADMIN 被拒绝；会员入口又需要 `member` 档案 + 认领码。

所以本次只放开**首次绑定**的角色限制，不改变已绑定用户的登录逻辑。

## 代码改动

### 后端

| 文件 | 改动 |
| --- | --- |
| `service/WechatAuthService.java` | 新增 `ROLE_ADMIN` 常量；`coachClaim` 允许 `COACH` 和 `ADMIN` 两种角色；仅当角色是 `COACH` 时强制要求教练档案，管理员可以没有档案；有档案时仍校验 `coach.status=1`；绑定日志的 `targetType/targetId` 在无档案时记为 `ADMIN/null`；响应里的名称无档案时返回「管理员」；`errorUrl(message, role)` 重载，把入口角色带回错误页 |
| `controller/WechatOauthController.java` | `/wechat/oauth/entry` 的异常分支调用带 role 的 `errorUrl`，保证「重试」仍从教练/管理员入口重新授权 |

绑定校验顺序保持：`票据 intent=COACH → 账号存在/启用 → 角色属于 COACH 或 ADMIN → BCrypt 密码 → 教练在职（若有档案）→ 核销票据 → 绑定`。
密码连续输错 5 次锁定 15 分钟、一个微信只能绑一个账号等既有安全限制不变。

### 前端

| 文件 | 改动 |
| --- | --- |
| `src/views/WechatCoachBindView.vue` | 文案改为「绑定管理端账号」「教练或管理员账号」「教练 / 管理员手机号」，解绑提示不再限定教练详情页 |
| `src/views/WechatEntryView.vue` | `retry()` 读取错误页 URL 上的 `role`，按进入时的身份重新授权；原来写死走会员入口 |

无需改数据库、无需改菜单配置：管理员继续使用现有「教练工作台」菜单（`role=COACH&redirect=/admin/workbench`）。

## 权限边界

- 仍然必须需要提供该账号的**手机号 + 正确密码**才能绑定，不会因为改了角色校验就任何人都能绑管理员微信。
- 绑定后签发的是账号本身的真实角色（ADMIN），管理员权限来自 `sys_user.role`，本次改动没有提权路径。
- `wechat_account` 唯一约束不变：同一个微信不能同时绑多个账号；同一账号也只能绑一个微信。
- 在职状态只在角色为 `COACH` 时校验 `coach.status`；管理员即使关联了一份已停用的教练档案，仍可用管理员身份绑定（与 `exchangeTicket` 的既有行为一致）。
- 管理员若**没有教练档案**，无法在「教练详情页」解绑（该页面按教练档案展示），需要解绑时执行下面的 SQL 或先给该账号补一条教练档案。

## 已知边界与残留问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| `/wechat/oauth/callback` 异常分支的错误页仍不带 `role` | 微信回调阶段报错（如 code 失效）时点「重试」仍走会员入口（这是改动前就有的行为，本次只修了 `entry` 异常分支） | 让用户重新点公众号菜单即可；如需彻底修复，需在 callback 捕获异常时从 state 中读出 role 再传给 `errorUrl` |
| `coach.user_id` 没有唯一约束 | 手工 SQL 曾给同一账号建多条教练档案时，`selectOne` 会报 `TooManyResultsException`（改动前就存在） | 上线前核对：`SELECT user_id, COUNT(*) FROM coach GROUP BY user_id HAVING COUNT(*) > 1` |
| 管理员解绑入口缺失 | 无教练档案的管理员，管理端没有可点的解绑按钮 | 用文档中的 DELETE SQL，或先给该账号补一条教练档案 |
| 前后端版本必须匹配 | 只更新前端时，绑定页文案变了但后端仍拒绝 ADMIN；只更新后端时，「重试」仍走会员入口 | 同时部署 `app.jar` 与 `dist` |

## SQL 变更

本次上线**没有 SQL 变更**，无需执行任何 DDL/DML。

验证与排障用只读 SQL：

```sql
-- 查看某管理员的账号状态与微信绑定
SELECT u.id, u.phone, u.role, u.status,
       w.id AS wechat_id, RIGHT(w.openid, 6) AS openid_tail
FROM sys_user u
LEFT JOIN wechat_account w ON w.user_id = u.id
WHERE u.phone = '13850943504';
```

需要解绑管理员微信时（等价操作，谨慎执行）：

```sql
DELETE FROM wechat_account WHERE user_id = (SELECT id FROM sys_user WHERE phone = '13850943504');
```

## 发布顺序

1. 部署后端 `app.jar`（`coachClaim` 角色放开 + `errorUrl` 重载）。
2. 部署前端 `dist`（绑定页文案 + 重试入口）。
3. 不需要数据库脚本，菜单配置也不用改（沿用「教练工作台」按钮）。

验收：

1. 管理员未绑定微信时点「教练工作台」→ 静默授权 → 绑定页。
2. 输入管理员手机号 + 密码 → 绑定成功 → 进 `/admin/workbench`。
3. 再次点菜单 → 免密直接进工作台。
4. 用会员手机号在绑定页提交 → 提示「该账号不是教练或管理员账号」。
5. 密码输错 5 次 → 锁定 15 分钟。
6. 教练侧原有绑定流程不受影响（仍要求在职教练档案）。
