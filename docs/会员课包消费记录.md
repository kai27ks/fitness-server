# 会员课包消费记录（课时流水）

## 背景

改造前系统里**没有课时流水表**：课包剩余课时只是 `member_package.remain_sessions` 一个数字，
消课只发生在签到那一刻（`deductOne`），过后无法追溯"哪一节、谁扣的、扣完剩多少"。

会员端「我的课包 → 消课记录」是前端用 `booking` 列表临时拼出来的：
- 购买记录写死一条「购买课包 N 节」；
- 用课程名匹配预约，签到/已完成就显示 -1，取消显示「无变动」；
- 管理端调课时、续购并入、旧数据导入都不会出现在记录里。

本次新增 `member_session_log` 表，把**所有改动剩余课时的动作**落成流水，会员端与管理端都读这张表。

## 数据模型

表 `member_session_log`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK | 自增 |
| `member_id` | BIGINT NOT NULL | 会员 |
| `package_id` | BIGINT NULL | 课包（`member_package.id`） |
| `booking_id` | BIGINT NULL | 签到扣课关联的预约 |
| `course_id` / `coach_id` | BIGINT NULL | 冗余，便于直接展示 |
| `type` | VARCHAR(20) | `CONSUME` 上课消课 / `PURCHASE` 购买续购 / `ADJUST` 管理端调整 / `IMPORT` 旧数据导入 |
| `change_sessions` | INT NOT NULL | 正数增加、负数扣减 |
| `remain_after` | INT NULL | 变动后剩余课时（历史回填为 NULL） |
| `remark` | VARCHAR(200) | 来源说明（课程时间、金额、调整原因等） |
| `operator_id` | BIGINT NULL | 操作人 `sys_user.id`，会员自助为空 |
| `create_time` | DATETIME | 发生时间 |

索引：`(member_id, create_time)`、`package_id`、`booking_id`。

## 写入点（全部代码位置）

| 业务动作 | 位置 | 流水类型 | 变动 |
| --- | --- | --- | --- |
| 到点自动签到扣课 | `BookingService.autoCheckIn` | `CONSUME` | -1 |
| 管理端补签 | `BookingService.manualCheckIn` | `CONSUME` | -1 |
| 新购课包 | `AdminMemberService.addPackage` | `PURCHASE` | +N |
| 续购并入（同会员同课程） | `AdminMemberService.addPackage` | `PURCHASE` | +N |
| 管理端课时调整 | `AdminMemberService.adjustSessions` | `ADJUST` | ±N |
| 旧会员 Excel 导入 | `MemberImportService.commit` | `IMPORT` | +N |

说明：

- 预约创建**不扣课时**（只校验余量），签到才扣，所以下单不会产生流水；
- 取消预约目前**不返还课时**（既有规则），因此取消不写流水；
- 扣课成功后才写流水，`deductOne` 返回 0（余量不足）时仍走原来的「课时异常」通知，不写假流水；
- 写流水失败只打日志，不影响签到主流程（与 `operation_log` 的处理一致）。

## 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/member/session-logs?packageId=&limit=` | 会员本人 | 只能查自己的流水，默认最近 100 条，最大 200 |
| GET | `/api/admin/members/{id}/session-logs?packageId=&limit=` | 管理员 / 教练 | 按会员查询，可按课包过滤 |

返回字段：`id, type, changeSessions, remainAfter, packageId, memberId, courseName, coachName, bookingTime, remark, createTime`。

## SQL 变更

### 1. 建表（必须执行）

```sql
CREATE TABLE IF NOT EXISTS member_session_log (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    member_id       BIGINT       NOT NULL COMMENT 'member.id',
    package_id      BIGINT       NULL COMMENT 'member_package.id',
    booking_id      BIGINT       NULL COMMENT 'booking.id（签到扣课关联）',
    course_id       BIGINT       NULL COMMENT 'course_template.id',
    coach_id        BIGINT       NULL,
    type            VARCHAR(20)  NOT NULL COMMENT 'CONSUME/PURCHASE/ADJUST/IMPORT',
    change_sessions INT          NOT NULL COMMENT '正数增加，负数扣减',
    remain_after    INT          NULL COMMENT '变动后剩余课时，历史回填可能为空',
    remark          VARCHAR(200) NULL,
    operator_id     BIGINT       NULL COMMENT '操作人 sys_user.id，会员自助场景为空',
    create_time     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY idx_member_time (member_id, create_time),
    KEY idx_package (package_id),
    KEY idx_booking (booking_id)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT '会员课包课时流水';
```

脚本文件：`docs/sql/20261120_member_session_log.sql`（已包含建表与下面的可选回填，幂等可重复执行）。

### 2. 历史消课回填（可选，建议执行）

上线前已签到/已完成的预约没有流水，可按下面语句补 `CONSUME` 记录；`remain_after` 留空（历史无法还原当时剩余），页面显示「—」。

```sql
INSERT INTO member_session_log
    (member_id, package_id, booking_id, course_id, coach_id, type, change_sessions, remain_after, remark, create_time)
SELECT b.member_id, b.package_id, b.id, b.course_id, b.coach_id,
       'CONSUME', -1, NULL, '历史数据回填（上线前已消课）',
       IFNULL(b.checked_in_at, b.start_time)
FROM booking b
WHERE b.status IN ('CHECKED_IN', 'COMPLETED')
  AND b.package_id IS NOT NULL
  AND NOT EXISTS (
      SELECT 1 FROM member_session_log l
      WHERE l.booking_id = b.id AND l.type = 'CONSUME'
  );
```

### 3. 执行后校验（只读）

```sql
-- 总览：各类型条数与节数合计
SELECT type, COUNT(*) AS rows_cnt, SUM(change_sessions) AS sum_change
FROM member_session_log
GROUP BY type;

-- 同一预约不应出现两条 CONSUME
SELECT booking_id, COUNT(*) AS cnt
FROM member_session_log
WHERE booking_id IS NOT NULL
GROUP BY booking_id
HAVING cnt > 1;

-- 某个会员的流水与课包余额核对（remain_after 取最后一条）
SELECT l.*, p.remain_sessions
FROM member_session_log l
LEFT JOIN member_package p ON p.id = l.package_id
WHERE l.member_id = /* 会员ID */
ORDER BY l.id DESC
LIMIT 20;
```

## 发布顺序

1. **先执行建表 SQL**（`docs/sql/20261120_member_session_log.sql` 第 1 段）；表不存在时新代码写入流水会失败（已做异常兜底，不会影响签到，但记录会丢）。
2. 部署后端 `app.jar`。
3. 执行可选的历史回填 SQL（建议在上线后、业务低峰执行，`NOT EXISTS` 保证幂等）。
4. 部署前端 `dist`。
5. 验证：
   - 会员端「我的课包 → 消费记录」能看到购买、消课、调整记录，节数与剩余正确；
   - 管理端会员详情「课时流水」同步显示；
   - 新建一笔预约 → 到点签到（或管理端补签）后刷新，出现一条 `-1 节` 的消课记录，`remain_after` 与课包余额一致；
   - 管理端 +1 / -1 调整后出现 `ADJUST` 记录；
   - 修改课时不影响历史流水的可读性。
