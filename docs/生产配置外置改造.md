# 生产配置外置改造（application-prod.yml 移出 jar）

日期：2026-11-26

## 一、需求

`application-prod.yml` 原来放在 `src/main/resources/` 下，会被打进 `app.jar`。改一次数据库密码 / 微信 secret 都得重新打包发版，不方便。要求把生产配置独立放到 jar 外面，并给出对应启动命令。

## 二、结论

配置改为外置，Spring Boot 启动时按「工作目录/config/」加载，优先级**高于** jar 内 classpath 配置：

| 环境 | 外置配置路径 |
| --- | --- |
| 本机（Windows） | `<项目根>/config/application-prod.yml` |
| 服务器（Linux） | `/opt/fitness/config/application-prod.yml` |

两者都是「工作目录下的 `config/`」，所以同一份文件两处通用，`deploy.sh` 与 systemd 都不用拼绝对路径清单。

## 三、改动清单

| 文件 | 改动 |
| --- | --- |
| `src/main/resources/application-prod.yml` | **删除**，不再打进 jar |
| `config/application-prod.yml` | **新增**，生产配置唯一来源（内容与原文件一致，上传目录保持相对路径 `./upload/*`） |
| `start-prod.cmd` | **新增**，本机以 prod profile + 外置配置启动后端的脚本 |
| `deploy.sh` | 新增 `CONFIG_DIR` / `CONFIG_FILE`；后端部署前校验外置配置存在（缺失直接报错并给出初始化命令）；配置纳入部署备份；jar 内若残留 `application-prod.yml` 打警告 |
| `src/main/resources/application.yml` | 两处注释改为指向外置配置路径 |
| `docs/第一版整体设计及服务器部署.md` | 6.4 后端部署步骤改为「配置外置 + systemd 注入 `SPRING_CONFIG_ADDITIONAL_LOCATION`」，补 `TZ=Asia/Shanghai`、权限约定 |
| `docs/公众号凭据配置.md`、`docs/开发维护联系方式.md`、`docs/会员风采展示设计.md` | 配置路径同步为外置路径 |

## 四、启动命令

### 4.1 本机（Windows，作用范围：这台电脑）

```cmd
cd /d C:\Users\user\IdeaProjects\jianshenfang
mvn -DskipTests clean package
start-prod.cmd
```

`start-prod.cmd` 等价于：

```cmd
set SPRING_CONFIG_ADDITIONAL_LOCATION=file:./config/
set TZ=Asia/Shanghai
java -Xms512m -Xmx1536m -jar target\app.jar --spring.profiles.active=prod
```

只要工作目录是项目根，`./config/` 会被自动扫描；`SPRING_CONFIG_ADDITIONAL_LOCATION` 显式写出，避免工作目录不对时读不到配置。改完 `config/application-prod.yml` 重新执行一次脚本即生效，不用重新打包。

### 4.2 服务器（systemd）

```bash
# 首次：把外置配置放到 jar 外面（600、root 属主，应用只读）
sudo mkdir -p /opt/fitness/config
sudo cp config/application-prod.yml /opt/fitness/config/application-prod.yml
sudo chown root:root /opt/fitness/config/application-prod.yml
sudo chmod 600 /opt/fitness/config/application-prod.yml
```

```ini
# /etc/systemd/system/fitness.service
[Unit]
Description=Fitness Studio API
After=network.target mysql.service

[Service]
User=ubuntu
WorkingDirectory=/opt/fitness
Environment="SPRING_CONFIG_ADDITIONAL_LOCATION=file:/opt/fitness/config/"
Environment="TZ=Asia/Shanghai"
ExecStart=/usr/bin/java -Xms512m -Xmx1536m -jar /opt/fitness/app.jar --spring.profiles.active=prod
Restart=always
RestartSec=5
StandardOutput=append:/var/log/fitness/app.log
StandardError=append:/var/log/fitness/app.log

[Install]
WantedBy=multi-user.target
```

改配置后的固定动作：

```bash
sudo systemctl restart fitness            # 只改 application-prod.yml 时，daemon-reload 不需要
sudo journalctl -u fitness -n 50 --no-pager
```

## 五、执行顺序

1. 拉取本次改动（`config/application-prod.yml` 已就位，`src/main/resources/application-prod.yml` 已删除）。
2. **必须 `mvn clean package`**，不能只 `package`：`target/classes` 里会残留上一版的 `application-prod.yml`，增量打包会把它重新塞回 jar（本次实测已踩到，`clean` 后 jar 内只剩 `application.yml` + `application-dev.yml`）。
3. 服务器首次部署：按 4.2 创建 `/opt/fitness/config/application-prod.yml`（600），再 `sudo systemctl daemon-reload`。
4. 上传新 `target/app.jar` → `sudo /opt/fitness/deploy.sh --backend-only`（脚本会自动校验外置配置存在）。
5. 本机：执行 `start-prod.cmd` 验证。
6. 验证：日志出现 `The following 1 profile is active: "prod"`，`/api/courses` 返回 `401`（未登录）即正常。

## 六、行为影响

- 以前配置错了要重新发版；现在改文件 + 重启即可，回滚配置也不用换 jar。
- 外置配置缺失时行为**刻意设计为快速失败**：jar 内已无 `application-prod.yml`，会退回 `application.yml` 默认值（无数据源）而启动失败，`deploy.sh` 会提前拦下，不会静默连错库。
- 生产密钥（数据库密码、`jwt-secret`、微信 secret）建议后续改为 systemd `Environment=` 或服务器 600 文件独占，仓库里的 `config/application-prod.yml` 只保留占位。

## 七、SQL 变更

**本次无 SQL 变更**，纯配置与部署脚本调整，无需执行任何 DDL / DML。
