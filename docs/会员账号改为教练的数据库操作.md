# 把会员账号改成教练（手工 SQL，仅测试用）

场景：手机号 `15805080815` 原本是会员（`sys_user.role = 'MEMBER'` + `member` 档案），测试时想让它直接以教练身份登录。
**这是非正常流程，程序不做兼容**，仅用于测试环境。

## 一、数据模型前提

| 表 | 关系 | 备注 |
| --- | --- | --- |
| `sys_user` | 登录账号，`role` 只能是 `ADMIN/COACH/MEMBER`，`phone` 唯一 | 角色存在 JWT 里，改库后必须重新登录 |
| `member` | 会员档案，`user_id` 唯一、`phone` 唯一 | 教练端接口不使用这张表 |
| `coach` | 教练档案，`user_id` 可空、**无唯一约束** | 教练端所有接口都靠 `coach.user_id = 当前登录 userId` 反查 |
| `wechat_account` | `user_id` 唯一 | 微信绑定关系，改角色不影响 |

要变成"能登录的教练"，必须同时满足：`sys_user.role='COACH'` **且** `coach` 表存在一条 `user_id = 该账号 id`、`status=1` 的记录。

## 二、操作步骤（MySQL）

### 1. 备份与核对（先看现状）

```sql
SET @phone = '15805080815';
SET @uid   = (SELECT id FROM sys_user WHERE phone = @phone);

SELECT @uid AS user_id;

SELECT id, phone, role, status FROM sys_user WHERE id = @uid;
SELECT id, user_id, name, phone, coach_id FROM member WHERE user_id = @uid;
SELECT id, user_id, name, status FROM coach WHERE user_id = @uid;
SELECT id, user_id, appid, RIGHT(openid, 6) AS openid_tail, nickname FROM wechat_account WHERE user_id = @uid;
```

建议先留一份回滚数据：

```sql
CREATE TABLE IF NOT EXISTS bak_coach_test_15805080815 AS
SELECT * FROM coach WHERE user_id = @uid;

-- 记录原角色
SELECT id, phone, role FROM sys_user WHERE id = @uid;  -- 结果手工记下，回滚用
```

### 2. 把账号角色改成教练

```sql
UPDATE sys_user SET role = 'COACH' WHERE id = @uid;
```

### 3. 补一条教练档案（若 `coach` 表里还没有该 `user_id` 的记录）

```sql
-- 用会员档案的名字作为教练名；已存在则不重复插入
INSERT INTO coach (user_id, name, status)
SELECT m.user_id, m.name, 1
FROM member m
WHERE m.user_id = @uid
  AND NOT EXISTS (SELECT 1 FROM coach c WHERE c.user_id = m.user_id);
```

如果这个人**本来就有教练档案**（例如档案已存在但 `user_id` 为空，或挂在旧账号上），改用：

```sql
-- 方式 A：把现有档案关联到这个账号（把 <coachId> 换成实际档案 id）
UPDATE coach SET user_id = @uid, status = 1 WHERE id = <coachId>;

-- 方式 B：先清掉旧账号的关联再改
UPDATE coach SET user_id = NULL WHERE user_id = @uid;  -- 若之前已有多余关联
```

> ⚠️ `coach.user_id` 没有唯一约束，**绝对不要出现两条相同 `user_id` 的记录**，否则 `currentCoach()` 的 `selectOne` 会报 `TooManyResultsException`。

### 4. 校验结果

```sql
SELECT u.id AS user_id, u.phone, u.role, u.status AS user_status,
       c.id AS coach_id, c.name AS coach_name, c.status AS coach_status,
       m.id AS member_id
FROM sys_user u
LEFT JOIN coach c ON c.user_id = u.id
LEFT JOIN member m ON m.user_id = u.id
WHERE u.id = @uid;
```

期望：`role=COACH`、`user_status=1`，`coach_id` 有值且 `coach_status=1`，`member_id` 仍在（测试态允许并存）。

### 5. 密码

无需改动，沿用会员账号原密码。若忘记密码，用管理端「教练详情 → 重置登录密码」，或直接调：

```
PUT /api/admin/coaches/{coachId}/account/password   body: {"newPassword":"123456"}
```

### 6. 微信绑定

`wechat_account.user_id` 没变，**无需操作**：改角色后从公众号「教练工作台」进入会直接免密登录进工作台。
若要复测"首次绑定"流程，再解绑：

```sql
-- 方式一：管理端调 DELETE /api/admin/coaches/{coachId}/wechat-bind
-- 方式二：直接删记录
DELETE FROM wechat_account WHERE user_id = @uid;
```

## 三、`member` 档案怎么处理

| 方案 | 操作 | 影响 |
| --- | --- | --- |
| **保留（推荐，测试够用）** | 不动 | 课包、预约、风采等历史数据都还在；但该账号 `role=COACH`，前端会员页会跳工作台 |
| 删除 | `DELETE FROM member WHERE user_id = @uid;` | `member_package`、`booking`、`media` 等按 `member_id` 关联的数据变成孤儿，测试库可接受，生产禁止 |

保留时要注意：`member.phone` 与 `sys_user.phone` 都是唯一的，**不能再用这个手机号新建会员/教练账号**。

## 四、回滚

```sql
SET @phone = '15805080815';
SET @uid   = (SELECT id FROM sys_user WHERE phone = @phone);

-- 角色改回会员
UPDATE sys_user SET role = 'MEMBER' WHERE id = @uid;

-- 删掉本次为测试新建的教练档案（保留原档案时跳过这步）
DELETE FROM coach WHERE user_id = @uid;
```

## 五、执行后必做

1. **重新登录**：JWT 里带的是旧角色 `MEMBER`，不重新登录仍会被判无权限。
2. 账密登录：登录后前端按 `role !== 'MEMBER'` 直接进 `/admin/workbench`。
3. 公众号入口：重新点一次「教练工作台」菜单（已绑定的微信直接进工作台）。
4. 快速自检：`GET /api/coaches/me` 应返回该教练档案；`GET /api/admin/dashboard` 应可访问（教练与管理员均允许）。

## 六、SQL 汇总（可直接执行）

```sql
SET @phone = '15805080815';
SET @uid   = (SELECT id FROM sys_user WHERE phone = @phone);

UPDATE sys_user SET role = 'COACH' WHERE id = @uid;

INSERT INTO coach (user_id, name, status)
SELECT m.user_id, m.name, 1
FROM member m
WHERE m.user_id = @uid
  AND NOT EXISTS (SELECT 1 FROM coach c WHERE c.user_id = m.user_id);

SELECT u.id, u.phone, u.role, c.id AS coach_id, c.name, c.status
FROM sys_user u LEFT JOIN coach c ON c.user_id = u.id
WHERE u.id = @uid;
```

本操作不涉及 DDL（建表/加字段/索引），只有上面两条 DML；若做了备份表，测试结束后可 `DROP TABLE bak_coach_test_15805080815;` 清理。
