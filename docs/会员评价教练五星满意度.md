# 会员评价教练：五星满意度

## 需求

参考淘宝闪购的五星评价：会员上完课后对教练打分，目前**只需要一个维度：满意度（1~5 星）**，不做文字标签、不做追评。

## 规则

- **谁能评**：会员本人，且该预约状态为 `CHECKED_IN`（已签到）或 `COMPLETED`（已完成）；
- **评什么**：一笔预约对应一位教练，评一次；
- **评几次**：一次课只能评一次（数据库唯一键 `uk_booking` 兜底，接口层先查出提示「该课程已评价」）；
- **不可修改**：本期不支持改评/追评；
- **谁能看**：会员端教练详情页看平均分与评价数；教练本人在「我的」看自己的满意度；管理端不展示。

## 数据模型

表 `coach_review`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT PK | 自增 |
| `member_id` | BIGINT NOT NULL | 评价人（`member.id`） |
| `coach_id` | BIGINT NOT NULL | 被评价教练（`coach.id`） |
| `booking_id` | BIGINT NOT NULL | 关联预约，**唯一键** |
| `rating` | TINYINT NOT NULL | 满意度 1~5 |
| `create_time` / `update_time` | DATETIME | 时间戳 |

索引：`UNIQUE uk_booking(booking_id)`、`idx_coach_time(coach_id, create_time)`、`idx_member(member_id)`。

## 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/bookings/{id}/review` | 会员本人 | body `{"rating": 5}`，返回该教练最新评分汇总 |
| GET | `/api/coaches/{id}/rating` | 登录用户 | 返回 `{count, average}`，用于教练详情页展示 |
| GET | `/api/coaches/me/reviews?limit=` | 教练 / 管理员 | 返回自己的 `{summary, items}`，会员姓名脱敏为「姓**」 |

评分汇总口径：`average = round(SUM(rating)/COUNT(*), 1)`，无评价时 `count=0, average=0`。

会员端预约列表新增字段（`BookingVO`）：
- `coachId`：教练 id；
- `rating`：该笔预约已提交的满意度，未评价为 `null`。

## SQL 变更

### 1. 建表（必须执行）

```sql
CREATE TABLE IF NOT EXISTS coach_review (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    member_id   BIGINT  NOT NULL COMMENT 'member.id',
    coach_id    BIGINT  NOT NULL COMMENT 'coach.id',
    booking_id  BIGINT  NOT NULL COMMENT 'booking.id，一次课只能评一次',
    rating      TINYINT NOT NULL COMMENT '满意度 1~5 星',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_booking (booking_id),
    KEY idx_coach_time (coach_id, create_time),
    KEY idx_member (member_id)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT '会员对教练的满意度评价';
```

脚本文件：`docs/sql/20261122_coach_review.sql`（幂等，可重复执行）。

### 2. 执行后核对（只读）

```sql
-- 各教练评分汇总
SELECT c.id, c.name, COUNT(r.id) AS review_count, ROUND(AVG(r.rating), 1) AS avg_rating
FROM coach c
LEFT JOIN coach_review r ON r.coach_id = c.id
GROUP BY c.id, c.name
ORDER BY avg_rating DESC;

-- 同一预约不应出现两条评价（正常无结果）
SELECT booking_id, COUNT(*) FROM coach_review GROUP BY booking_id HAVING COUNT(*) > 1;

-- 某会员的评价明细
SELECT r.*, b.start_time, c.name AS coach_name
FROM coach_review r
LEFT JOIN booking b ON b.id = r.booking_id
LEFT JOIN coach c ON c.id = r.coach_id
WHERE r.member_id = /* 会员ID */
ORDER BY r.id DESC;
```

### 3. 回滚

```sql
DROP TABLE IF EXISTS coach_review;
```

## 发布顺序

1. **先执行建表 SQL**（表不存在时提交评价会报错）。
2. 部署后端 `app.jar`（新接口 + `BookingVO` 多了两个字段，前端需同步）。
3. 部署前端 `dist`。
4. 验证：
   - 用会员账号打开「我的预约 → 已完成」，点「评价教练」，选择 4 星提交 → 提示成功并显示「★★★★☆ 已评价」；
   - 同一预约再次进入不再显示评价入口（后端重复提交返回「该课程已评价」）；
   - 待上课的预约没有评价入口；
   - 教练详情页平均分、评价数随评价增加而变化；
   - 教练账号「我的」能看到自己的满意度。

## 后续可扩展

- 增加文字评价、标签（专业度/态度/守时等）：在 `coach_review` 加列或加子表即可，`rating` 仍是主维度；
- 允许修改/追评：去掉唯一键限制或加 `updated` 历史表；
- 管理端评价列表与举报处理：新增 `/api/admin/reviews` 分页接口。
