# 公众号入口登录报 404 排查与修复

日期：2026-11-15

## 一、现象

从微信公众号（测试号）入口登录时，后端打出：

```
ERROR ... c.j.common.GlobalExceptionHandler : 系统异常
org.springframework.web.servlet.resource.NoResourceFoundException: No static resource ...
    at org.springframework.web.servlet.resource.ResourceHttpRequestHandler.handleRequest
```

前端/用户侧看到「系统繁忙，请稍后再试」，看起来像后端崩了。

## 二、根因

### 1. 报错被误判为 500（已修复）

Spring Framework 6.1 起，**没有匹配到任何 Controller 的请求**（包括路径写错、少一段、多一个 `/`）
不再静默返回 404，而是抛 `NoResourceFoundException`（框架会把它当静态资源去找）。
`GlobalExceptionHandler` 的 `@ExceptionHandler(Exception.class)` 兜底把它接住，
于是 404 被当成「系统异常」记 ERROR 堆栈、返回 `code=500`。

修复：单独处理该异常 → 记录 `warn`（带真实路径）并返回 HTTP 404 + `code=404`。

### 2. 路径为什么会不存在

`/wechat/` 下只有 3 个后端地址：

| 地址 | 归属 | 说明 |
| --- | --- | --- |
| `/wechat/oauth/entry` | 后端 | 公众号菜单入口，302 到微信授权 |
| `/wechat/oauth/callback` | 后端 | 微信授权回调，换 openid 后 302 回前端 |
| `/wechat/event` | 后端 | 服务器配置校验 / 关注事件推送 |
| `/wechat/entry`、`/wechat/bind`、`/wechat/follow` | **前端（Vue Router）** | 授权完成后的落地页 |

因此 404 的路径基本可以锁定为 **`/wechat/entry`（前端路由）被打到了后端 8080**，成因：

- 内网穿透（花生壳）**指向了 8080**，而不是前端 5173；
- 或菜单 URL 填成了 `/wechat/entry`（少了 `/oauth`）；
- 或生产 Nginx 没有 `/wechat/` 反代（/wechat/oauth 也进不了后端）。

## 三、改动内容

| 文件 | 改动 |
| --- | --- |
| `src/main/java/com/jianshenfang/common/GlobalExceptionHandler.java` | 新增 `@ExceptionHandler(NoResourceFoundException.class)`：warn 日志打印真实路径，返回 HTTP 404 + `{"code":404,"message":"接口不存在：/xxx"}`，不再走「系统异常」兜底 |
| `docs/公众号自定义菜单.md` | 补充「隧道必须指向 5173」「生产 Nginx 需补 `/wechat/oauth/`、`/wechat/event` 反代」两条部署约束 |

## 四、如何确认具体是哪个路径

重启后端后，从公众号菜单再点一次，看日志里新增的一行：

```
WARN ... 请求路径不存在: /wechat/entry
```

- 显示 `/wechat/entry` → 隧道/代理把前端路由转给了后端，**把隧道改指 5173**（或生产 Nginx 按上面的规则拆开）
- 显示 `/wechat/oauth` 或 `/wechat/oauth/entry/` 之类 → 菜单 URL 写错，改成
  `https://<域名>/wechat/oauth/entry?redirect=/`
- 显示其它 `/api/xxx` → 前端调用了不存在的接口，按路径补接口或改调用

## 五、正确的入口地址

```
https://13230zl69xe33.vicp.fun/wechat/oauth/entry?redirect=/
```

- 必须是 `/wechat/oauth/entry`，不是 `/wechat/entry`
- 域名要与测试号「网页授权获取用户基本信息」里登记的域名完全一致
- 该域名对应的服务（Vite 5173 / Nginx 静态站）必须在运行

## 六、后续问题：微信报 10003（redirect_uri 域名与后台配置不一致）

现象：手机微信弹出「微信登录失败，redirect_uri 域名与后台配置不一致，错误码 10003」。

说明链路已通（请求到了后端并 302 到微信），只是**测试号后台登记的授权域名**与后端拼出来的
`redirect_uri` 域名不同。

后端拼出的 redirect_uri：

```
https://<wx.callback-base-url>/wechat/oauth/callback
# dev 实际为：https://13230zl69xe33.vicp.fun/wechat/oauth/callback
```

处理：测试号后台 →「网页帐号 / 网页授权获取用户基本信息」→ 修改，域名填

```
13230zl69xe33.vicp.fun
```

填写规则：

- 只填域名，不带 `https://`、不带路径、不带末尾 `/`、不带端口
- 微信只比对**域名**，路径不参与比较；域名不同（如 `kai27ks.cn`）就报 10003
- 测试号只能登记一个域名：测隧道就用隧道域名，测生产改成 `kai27ks.cn` 并同步改 `wx.callback-base-url`
- 保存后等 1~2 分钟，杀掉微信进程重进再点菜单（微信客户端会缓存授权配置）

## 七、SQL 变更

**本次无 SQL 变更**，只改了异常处理器与文档，无需执行任何 DDL/DML。

## 八、执行顺序

1. 重新编译/启动后端（`dev` profile）
2. 确认内网穿透指向 5173，前端 `npm run dev` 在跑
3. 公众号菜单 URL 使用 `/wechat/oauth/entry?redirect=/`
4. 手机重新进入菜单，日志应无 ERROR；若仍失败，按第四节看 warn 日志定位
5. 生产上线前，按《公众号自定义菜单.md》补 Nginx 的 `/wechat` 反代
