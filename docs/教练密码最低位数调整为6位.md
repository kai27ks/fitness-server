# 教练密码最低位数调整为 6 位

## 需求

教练登录密码的下限从 8 位改为 6 位（上限保持 64 位不变）。

## 改动内容

后端：

- `CoachAccountService.requirePassword`：长度校验 `password.length() < 8` 改为 `< 6`，提示文案改为「请设置6～64位密码」。该方法同时用于「开通/关联登录账号（CREATE）」和「重置登录密码」两条链路，因此两处规则一并生效。
- `CoachAccountDtos.ResetPassword`：`@Size(min = 8, ...)` 改为 `@Size(min = 6, ...)`，提示「新密码需为6～64位」。
- 上限与安全兜底不变：最长 64 位，且 UTF-8 字节数仍限制 72 字节（BCrypt 限制）。

前端：

- `CoachAccountPanel.vue`：密码校验函数下限改为 6，提示「请设置6～64位密码」；重置密码、创建账号的 4 个密码输入框 `minlength` 改为 6、占位文案改为「6～64位密码」。
- `CoachesView.vue`：新增教练时「开通登录账号」的初始密码校验下限改为 6，提示「请设置6～64位初始密码」，两个输入框的 `minlength` 与占位文案同步调整。

文档：

- `docs/教练登录账号管理.md` 中的密码位数描述同步改为 6～64 位。

## 兼容性说明

- 账号密码在 `sys_user.password` 中以 BCrypt 哈希保存，位数规则只是创建/重置时的校验条件，**存量密码不受影响**，原先 8 位及以上的密码仍可正常登录。
- 6～7 位的密码安全性降低，属于业务侧明确要求；如需限制弱口令，可后续再加复杂度校验（数字/字母组合等）。

## SQL 变更

本次上线**没有 SQL 变更**，无需执行任何 DDL 或 DML。

如上线后需核对教练账号情况（只读，不含密码）：

```sql
SELECT c.id AS coach_id, c.name, c.user_id,
       u.phone AS login_phone, u.role, u.status
FROM coach c
LEFT JOIN sys_user u ON u.id = c.user_id
ORDER BY c.id;
```

## 发布顺序

1. 部署后端 `app.jar`（校验规则与 DTO 注解）。
2. 部署前端 `dist`（表单 `minlength` 与提示文案）。
3. 无需执行数据库脚本。
4. 验证：管理端「教练详情 → 重置登录密码」输入 6 位密码应保存成功；输入 5 位应提示「请设置6～64位密码」；用新设置的 6 位密码可登录教练端。
