# 教练侧公众号自动登录 · 设计方案

日期：2026-11-15
现状参考：`WechatAuthService`（会员侧网页授权 + 认领）、`docs/公众号自定义菜单.md`

## 一、目标

在**同一个测试号**下增加「教练工作台」入口，教练点菜单即免密进入教练端；
首次进入需用「手机号 + 密码」绑定一次微信，之后永久免密。

## 二、整体链路（与会员侧共用底座）

```
公众号菜单 → /wechat/oauth/entry?role=COACH&redirect=/admin/workbench
   ↓ 302（state 里带 role）
open.weixin.qq.com 网页授权（snsapi_base 静默）
   ↓
/wechat/oauth/callback?code&state → 换 openid → 查 wechat_account
   ├─ 已绑定 → 发 CLAIM_TICKET(userId) → 302 到 H5 /wechat/entry?ticket=
   └─ 未绑定 → 发 CLAIM_TICKET(intent=COACH) → 同一落地页，前端跳绑定页
   ↓
/wechat/entry 调 /api/auth/wechat/ticket 换 JWT → role=COACH → /admin/workbench
```

**复用**：state 反 CSRF、一次性 ticket 表、`authService.loginSuccess` 签发 JWT、菜单创建接口、
`/wechat/entry` 已有的「非 MEMBER 跳工作台」逻辑。

## 三、与会员侧的核心差异（重点）

| 维度 | 会员侧（已实现） | 教练侧（本设计） |
| --- | --- | --- |
| 菜单项 | 会员中心 | 教练工作台 |
| 入口 | `/wechat/oauth/entry?redirect=/` | `/wechat/oauth/entry?role=COACH&redirect=/admin/workbench` |
| 授权 scope | `snsapi_userinfo`（要头像昵称上风采墙） | **`snsapi_base`（静默，不弹授权页，快）** |
| 未绑定引导 | `/wechat/bind`：手机号 + **认领码** | `/wechat/coach-bind`：手机号 + **密码** |
| 校验强度 | 手机号命中会员档案 + 认领码未用/未过期/失败次数上限 | 手机号 → 账号 `role=COACH` + **BCrypt 密码校验** + 失败锁定 + `coach.status=1` |
| 手机号未命中 | 写入 `wechat_claim_request` 待前台核实，**不建档** | **直接拒绝**，不进队列（教练账号必须后台先建） |
| 绑定目标 | `member` + `sys_user` | `coach.user_id` + `sys_user` |
| 登录后落地 | `redirect`（默认 `/`） | `/admin/workbench` |
| JWT 角色 | `MEMBER` | `COACH`（可进 `/admin/*`） |
| 审计 | 不强制 | **每次登录/绑定/解绑写 `operation_log`** |
| 停用处理 | 账号停用 → 拒绝 | `coach.status=0` 或 `user.status=0` → **拒绝并提示"账号已停用，请联系店长"** |
| 解绑 | 管理端按 `memberId` | 管理端按 `coachId`（新增接口） |
| 模板消息 | 预约成功/上课提醒/取消 | 暂无（后续可加排课变更通知） |

## 四、关键设计决策

### 1. 一个公众号，两个菜单入口

同一个测试号只能有一套菜单（最多 3 个一级 / 每个 5 个二级），所以用两个一级按钮区分身份：

```json
{
  "button": [
    { "type": "view", "name": "教练工作台",
      "url": "https://13230zl69xe33.vicp.fun/wechat/oauth/entry?role=COACH&redirect=/admin/workbench" },
    { "type": "view", "name": "会员中心",
      "url": "https://13230zl69xe33.vicp.fun/wechat/oauth/entry?redirect=/" }
  ]
}
```

「教练工作台」5 个汉字 = 15 字节，未超 16 字节上限。

### 2. `role` 参数必须由服务端签发到 state 里

不能在 callback 里直接读 URL 上的 `role`（可被篡改），流程是：

- `entry?role=COACH` → 校验白名单后写入 state payload `{redirect, role}`
- callback 只信 state 里的 role → 决定 scope 已用值、ticket 里的 `intent`
- 绑定接口校验 `intent=COACH`，防止用会员票去调教练绑定

### 3. 教练用 `snsapi_base`，会员保持 `snsapi_userinfo`

- `snsapi_base` 静默授权，点菜单直接进，无「是否允许」弹窗——教练高频使用，体验优先
- 教练头像/昵称用管理端已上传的资料，不需要微信头像
- `snsapi_base` 拿不到昵称头像，回调里 `getJson(userinfo)` 逻辑要跳过（按 scope 判断，已实现）

### 4. 绑定方式：密码而不是认领码

会员认领码是小票上印的一次性码，泄露风险可接受（只能看自己的课包）；
教练权限高（可看全体会员手机号、代约、排课），必须用**账号密码**二次校验：

- 手机号 → 查 `sys_user`，`role` 必须是 `COACH` 且 `status=1`
- BCrypt 校验密码
- 失败 5 次锁定 15 分钟（同 openid + 同手机号维度）
- 成功后写 `wechat_account(user_id, appid, openid)`
- 反向校验：若该微信已绑定的是 MEMBER 账号 → 提示「当前微信绑定的是会员账号，请从会员中心进入」

### 5. 身份与绑定的数据模型：当前**不需要改表**

`wechat_account` 现有约束：

- `UNIQUE(user_id)`：一个账号只能绑一个微信
- `UNIQUE(appid, openid)`：一个微信只能绑一个账号

而 `sys_user.phone` 唯一 + `role` 单值，意味着**一个自然人只能有一个账号**，
所以「同一个微信既是会员又是教练」在当前模型下不可能出现，**无需给 `wechat_account` 加 role 列**。

身份判断统一走 `sys_user.role`：ticket 换 JWT 时由 `loginSuccess(user)` 带出，
`/wechat/entry` 已经按 `res.role === 'MEMBER'` 分流落地。

> 若未来要支持「一个人同时是会员和教练」（两个账号、同一微信），再升级为
> `wechat_account` 加 `role` 列 + 唯一键改 `(appid, openid, role)`，见第八节备选 DDL。

### 6. 落地页复用，只多一个绑定页

`/wechat/entry` 现有逻辑已满足：

- 换到 token 且 `role != MEMBER` → 跳 `/admin/workbench`
- `needClaim=true` → 跳绑定页（现在固定 `/wechat/bind`）

需要小改：绑定页由 `claimTicket` 里的 `intent` 决定
（`intent=COACH` → `/wechat/coach-bind`，否则 `/wechat/bind`）。

### 7. 离职与解绑

- 每次 `exchangeTicket` 都要校验：`sys_user.status=1`，且 `role=COACH` 时 `coach.status=1`
- 管理端教练详情页加「解绑微信」按钮（删除 `wechat_account` 记录）
- 停用教练后，即使已绑定也进不去（校验在换 token 时，不依赖前端）

## 五、接口清单

### 改造

| 接口 | 改动 |
| --- | --- |
| `GET /wechat/oauth/entry` | 新增 `role` 参数（`MEMBER` 默认 / `COACH`），写入 state，按 role 选 scope |
| `GET /wechat/oauth/callback` | 从 state 读 role，传给 `finish()` |
| `POST /api/auth/wechat/ticket` | 返回 `needClaim` 时附 `intent`；换 JWT 前校验 coach 状态 |

### 新增

| 接口 | 说明 |
| --- | --- |
| `POST /api/auth/wechat/coach-claim` | body `{claimTicket, phone, password}`；校验 intent=COACH、role=COACH、密码、coach 在职；成功绑定并返回 JWT |
| `DELETE /api/admin/coaches/{id}/wechat-bind` | 管理端解绑教练微信（写审计） |

## 六、前端改动

| 文件 | 改动 |
| --- | --- |

## 七、验收清单

1. 教练首次点「教练工作台」→ 静默授权（无弹窗）→ 绑定页 → 输手机号+密码 → 进工作台
2. 再次点菜单 → 直接进工作台，无绑定页
3. 密码输错 6 次 → 提示锁定，15 分钟内即使密码正确也拒绝
4. 用会员手机号在教练绑定页提交 → 提示「该账号不是教练账号」
5. 停用该教练（`coach.status=0`）→ 再点菜单 → 提示账号已停用
6. 管理端解绑微信 → 再点菜单 → 回到绑定页
7. 会员点「教练工作台」且未绑教练 → 不得进入 `/admin/*`，提示走会员中心
8. 会员侧原有链路不受影响（认领码、风采墙、模板消息）

## 八、SQL 变更

**当前方案（推荐）：无 DDL 变更**，仅代码改动。

备选（未来支持一人多身份时才需要）：

```sql
ALTER TABLE wechat_account ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'MEMBER' AFTER user_id;
ALTER TABLE wechat_account DROP INDEX uk_appid_openid;
ALTER TABLE wechat_account ADD UNIQUE KEY uk_appid_openid_role (appid, openid, role);
```

## 九、实施顺序

1. 后端：`entry` 支持 role → state/callback 透传 → ticket 返回 intent → coach 状态校验
2. 后端：新增教练绑定接口 + 解绑接口（含失败计数与审计）
3. 前端：`CoachBindView` + 落地分流 + 教练详情解绑入口
4. 公众号菜单：调 `POST /api/admin/wechat/menu` 下发两个入口
5. 按第七节验收，先测「首次绑定 → 免密登录 → 停用/解绑」三条主线
