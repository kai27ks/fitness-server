# 公众号 appid / secret 配置记录（区分环境）

日期：2026-11-15

## 一、需求

把公众号 `appid` / `secret` 记录到配置文件里，并按环境区分（本地测试号 / 生产正式号）。

## 二、当前凭据一览

| 环境 | 配置文件 | appid | secret |
| --- | --- | --- | --- |
| dev（本地） | `src/main/resources/application-dev.yml` | `wxdc874e48e6e85235` | `c16a801e5e8cb801136582c8d9ac51f9` |
| prod（生产） | `src/main/resources/application-prod.yml` | 待填（`${WX_APPID:}`） | 待填（`${WX_SECRET:}`） |
| 任意环境覆盖 | 环境变量 | `WX_APPID` | `WX_SECRET` |
| 本机临时覆盖 | `config/wechat-dev.properties`（已 gitignore） | — | 同上值 |

dev 的这组就是接口测试号「akai2295的接口测试号」的凭据，可直接调
`https://api.weixin.qq.com/cgi-bin/token?appid=wxdc874e48e6e85235&secret=c16a801e5e8cb801136582c8d9ac51f9&grant_type=client_credential`
换 token。

## 三、配置优先级

```
环境变量 WX_APPID / WX_SECRET
  > config/wechat-dev.properties（spring.config.import 导入，已 gitignore）
    > application-dev.yml / application-prod.yml 的默认值
      > application.yml 的空兜底
```

注意：`config/wechat-dev.properties` 的优先级**高于** `application-dev.yml`。如果改了 yml 却不生效，先检查这个文件里是否有同名项。

## 四、改动内容

| 文件 | 改动 |
| --- | --- |
| `src/main/resources/application-dev.yml` | 补上 `wx.secret`（原只写在 gitignore 的 config 文件里，换机器会丢）；注释说明是接口测试号及优先级 |
| `src/main/resources/application-prod.yml` | 新增 `wx.appid` / `wx.secret` 占位（`${WX_APPID:}` / `${WX_SECRET:}`），注释强调与 dev 分开、不可混用 |
| `src/main/resources/application.yml` | 注释由「勿把密钥写进仓库」改为「各环境分别在 dev/prod 配置，环境变量优先级最高」 |
| `config/wechat-dev.properties` | 注释补充优先级说明（本文件优先于 application-dev.yml） |

## 五、生产环境怎么填

二选一：

1. **推荐**：服务器 `/opt/fitness/application-prod.yml`（权限 600，`deploy.sh` 不会覆盖）或 systemd `Environment=` 注入
   ```ini
   Environment=WX_APPID=wx********
   Environment=WX_SECRET=********
   ```
2. 直接改仓库里的 `application-prod.yml`，把 `:` 后的占位换成真实值

> 当前生产正式号的 appid/secret 尚未提供，故 prod 保持占位；测试号的凭据**不能**用于生产域名，否则网页授权回调域名对不上。

## 六、验证

启动对应 profile 后：

```bash
curl https://13230zl69xe33.vicp.fun/api/admin/wechat/access-token \
  -H "Authorization: Bearer <管理员JWT>"
```

返回 `code=0` 且有 `accessToken` 即凭据有效；返回「请检查 wx.appid / wx.secret 是否已配置」说明没读到。

## 七、安全提醒

- `application-dev.yml` 里现在是明文 secret，会随仓库提交。若仓库对外可见，建议把该值换成环境变量注入，或在测试号后台重置 secret。
- 生产 secret 建议只放服务器 `application-prod.yml`（600）或环境变量，不要提交到仓库。
- 若 dev/prod 用同一个公众号，两边值可以相同；但**测试号与正式号必须分开**。

## 八、SQL 变更

**本次无 SQL 变更**，纯配置文件调整，无需执行任何 DDL/DML。

## 九、执行顺序

1. 本地：重启后端（`dev` profile），确认 `GET /api/admin/wechat/access-token` 能返回 token
2. 生产：在服务器填好 `WX_APPID` / `WX_SECRET` 后重启 `fitness` 服务
3. 用返回的 token 继续调 `cgi-bin/menu/get` / `cgi-bin/menu/create`（见《公众号自定义菜单.md》）
